# Windows 微信选择工作流

工具签名及权限规则以当前 Agent 实际安装的桌面控制工具为准。没有桌面工具时请用户执行选择步骤，Agent 仍可接收和读取文件。不要固化坐标、快捷键、元素索引或特定微信版本的菜单结构。

## 工具与观察

Codex Windows 适配：使用 `node_repl`，按 Computer Use 技能初始化 `@oai/sky`。`sky.list_apps()` / `list_windows()` 返回真实窗口后，过滤微信而非开发者工具，得到唯一目标再调用 `get_window`。下面的工具示例仅适用于提供该接口的环境；其他 Agent 使用其实际桌面工具完成同样的观察与操作，不照抄未提供的 API。

需要控件文本时调用（`wxWindow` 必须来自实际窗口选择）：

```javascript
globalThis.wxState = await sky.get_window_state({
  window: wxWindow, include_screenshot: false, include_text: true,
});
globalThis.wxWindow = wxState.window;
nodeRepl.write(wxState.accessibility?.tree || "");
```

控件信息不足时另取截图，查看后再决定点击位置。不要假设微信消息项支持 UIA SelectionItem/Toggle；只用实际观察到的控件或截图。

遵守“观察并结束本次调用 → 阅读结果 → 一个动作并立即刷新”的两次调用循环。每次点击、滚动、弹出菜单后，旧索引和坐标作废。输入聊天名或关键词前单独确认焦点，避免写进聊天输入框。

不要批量盲点多行。滚动从消息区实际观察到的位置发起，不滚动侧边会话列表。每次核对选中计数或勾选状态；工具调用成功不是选中成功的证据。

## 定位会话

1. “当前聊天”读取当前标题；多窗口时利用标题和用户范围辨别，无法辨别才询问。
2. 指定群名或联系人时，通过实际可见的会话搜索入口输入名称。
3. 重名时用用户信息和可见标识缩小范围，不任意打开第一个结果。
4. 进入聊天后再次确认标题，再定位消息。

## 最近 N 条

1. 确认消息区在最新位置。不要假定切换聊天自动位于底部；利用滚动、可见“回到最新”按钮或实际导航。
2. 记录末条锚点：聊天名、可见时间、发言人、消息类型及必要短片段。无准确时间时不补造。
3. 右击一条已观察到的消息，读取菜单；点击实际存在的“多选”。进入后核对该消息是否自动选中。
4. 每次新观察后选择下一条。媒体、长文本和引用回复高度不同，不能按固定行高批量计算。
5. 跨屏保持边界重叠，核对已选状态，防止重复点击取消选择。状态无法判断时重新观察；不能恢复可靠判断就报告已完成范围。
6. 完成后核对界面计数。少于 N 条时，只有界面证明已到历史起点才可称为“该聊天不足 N 条”，否则只报告加载/找到的条数。

## 时间和主题

日期筛选、搜索类型和“定位到聊天”入口以实机观察为准。搜索命中只是线索；需要上下文时进入原聊天检查。关键词未命中不能证明主题不存在。

“昨天”按用户时区解释为昨天 00:00 到今天 00:00。导出时间可能只有分钟精度；边界同分钟的消息应说明限制。界面不显示每条时间时，不从相邻消息虚构精确时间。

语义筛选记录保留理由，区分命中消息和为理解它保留的上下文。只要求匹配消息时不扩大范围；需要扩大才能判断时说明所需范围。

## 批次与恢复

单次上限由当前界面决定，不把文档中的 100 硬编码为所有版本上限：

- `select`：保留已选状态，说明一个选择集不能容纳全部目标。
- `export`：先导出并验证当前批次，保留起止锚点，再继续下一批。每批刷新收件箱基线，已验证批次单独列出。

新消息插入、窗口切换或用户接管后重新观察；不能恢复锚点就停止当前批次。同一无进展界面最多重新观察重试一次，随后报告阻塞。短请求已经滚动很多屏仍找不到边界时，说明进度并澄清范围，不无限遍历。

## 实机用例

用户开始验证后按其指定范围操作，不用任意私人聊天测试：最近 5 条（含文字和图片）、跨屏最近 20 条、导出并核对同一批 20 条、明确半小时时间范围、范围内主题筛选、接收器入口缺失时的停止行为。未做过的用例标为未验证。
